## Q1. ステートレス API とクライアント側履歴管理

LLM API はなぜステートレスなのですか？
サーバー側にセッションを持たせない理由を2つ挙げてください。

> A.
1. スケーラビリティ: サーバがスケールアウトできるようにするため
2. LLM固有事情: 課金の透明性, コンテキストの柔軟性

---

## Q2. 履歴の積み方

毎ターン `messages` リストに追加する内容を、順番に書いてください。
「APIを呼ぶ前」と「呼んだ後」で何をするかを区別して説明してください。

> A.
1. APIを呼ぶ前: "role": "user"をセット
2. APIを呼んだ後: API Responseに含まれる text を設定 ("role": "assistant")

---

## Q3. `messages = []` の置き場所

`messages = []` をループの外に置いた理由は何ですか？
ループの中に置いたらどうなりますか？

> A.
ループの外に置いた理由は会話履歴を積んでいくため
ループの中に置いたら会話ごとに初期化されてしまう

## Q4. input_tokens の増加

会話を重ねるたびに `input_tokens` が増えていきました。なぜですか？
`max_tokens=1024` とは何が違いますか？

> A.
- これまでの会話内容も合わせて送信するため input_tokens が増えていく
max_tokens はレスポンスの最大トークン数（文字数ではない）。
トークンは文字と1対1ではなく、日本語は1文字が複数トークンになることが多い（例:「東」= 2〜3トークン）。英語は1単語≒1〜2トークン。
つまり max_tokens=1024 が実際に何文字に相当するかは言語によって異なる。

## Q5. Context Window との関係

今回の実装は、会話が十分に長くなると理論上どんな問題が起きますか？
それを解決するにはどんなアプローチが考えられますか？（実装しなくてOK）

> A.
会話が十分に長くなるとContext Windowが溢れ、会話のコンテキストが欠落する
それを解決するために会話を圧縮するアプローチがあり得る

>
理論を覚えると日々何気なく利用しているChatの活用方法も工夫ができそう。
例: Claude.ai で長い会話中に「さっきの話を忘れたように感じる」現象は、Context Window の制限でアプリ側が古い履歴を切り捨てているから。仕組みを知っていれば「新しいチャットを始めて要点を再共有する」という対処ができる。
