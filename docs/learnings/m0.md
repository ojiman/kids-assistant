## Q1. 環境変数とSDKの連携

`load_dotenv()` と `Anthropic()` はそれぞれ何をしていますか？
なぜ `load_dotenv()` を先に呼ばなければいけないのですか？

> A.

- load_dotenv(): コードベースにある .env の内容を、Pythonプロセスの環境変数にロードしている。具体的には os.environ に書き込まれている。
- Anthropic(): Anthropic Clientの初期化が行われ、 os.environ["ANTHROPIC_API_KEY"] を読み込んでいる。
- 順番の理由: Anthropic() は初期化時に os.environ を読みに行くため、その前に load_dotenv() で環境変数を展開しておく必要がある。逆にすると API キーが見つからず失敗する。

## Q3. システムプロンプト

`system=` を変えると応答がどう変わりましたか？
システムプロンプトは `messages` の中に書くのと何が違いますか？

> A.

system はLLMに前提として渡す情報。
messagesに記載すると one time のやりとりだけだが、
systemに記載することで当該セッションにおいて永続的に適用される。

## Q5. `role` フィールド

レスポンスに `role: "assistant"` が含まれていました。
このフィールドは M1（会話履歴）でどう使われると思いますか？

> A.

LLM API はステートレスで、前の会話を一切覚えていない。「さっき何を話したか」を伝えるには、毎ターン全履歴を messages に積んで送る必要がある。

```python
messages=[
    {"role": "user",      "content": "空はなぜ青いの？"},
    {"role": "assistant", "content": response.content[0].text},  # ← ここに前の返答を入れる
    {"role": "user",      "content": "じゃあ夕焼けはなぜ赤いの？"},
]
```

role: "assistant" の content には response.content[0].text を入れる。
ChatGPT や Claude.ai がステートフルに見えるのは UI の仕事で、APIは毎回「初めて見た」として処理している。
