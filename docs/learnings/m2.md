# M2 学習まとめ：Tool Use とエージェントループ

---

## Q1. ツール定義の役割

`tools` リストをAPIに渡す目的は、ユーザーのプロンプトに特定の指示があった場合に実行するプログラムを定義することです。
`description` は、モデルが「このツールをいつ使うべきか」を判断するために参照されます。description の書き方がツールの使われ方を左右します。

---

## Q2. stop_reason の意味

- `tool_use`: モデルがツールの実行を要求している。コード側でツールを実行して結果を返す必要がある。
- `end_turn`: 当該ターンの応答が完了した（セッション全体の終了ではなく、1ターン分の応答が終わったという意味）。

コードでは内側ループの分岐条件として使っている。`tool_use` なら処理してループ継続、それ以外（`end_turn`）なら `break`。

---

## Q3. エージェントループの構造

内側の `while True` は、必要な回数だけツール実行を繰り返すためにあります。ツールを1つ呼んだ後、モデルがさらに別のツールを要求することもあるため、`end_turn` になるまでループします。

「123かける456は？」と聞いたとき、内側ループは2回回りました。

- **1回目**: API → `stop_reason: "tool_use"` → multiply(123, 456) を実行 → tool_result を messages に追加 → ループ継続
- **2回目**: API → `stop_reason: "end_turn"` → テキスト応答を返す → break

---

## Q4. messages に積む順番

`stop_reason: "tool_use"` のとき：

1. `{"role": "assistant", "content": response.content}` ← モデルがツールを呼んだ記録
2. `{"role": "user", "content": [{"type": "tool_result", ...}]}` ← 実行結果

順番の理由: APIは「モデルがツールを呼んだ」という事実（1）を見た後でないと、「その結果」（2）がどのツールに対するものか分かりません。逆順にすると API がコンテキストを理解できなくなります。

---

## Q5. tool_result の構造

1回の応答でモデルが複数のツールを同時に呼ぶことがあります。

```python
response.content = [
    ToolUseBlock(id="aaa", name="multiply", ...),
    ToolUseBlock(id="bbb", name="search", ...),
]
```

このとき `tool_result` を返す側は「どの `tool_use` に対する結果か」を明示しないと API が対応できません。`tool_use_id` はそのマッピングのためにあります。

---

## Q6. ハーネスとの関係

LangChain や Agent SDK を利用するとエージェントループは内部に隠蔽されます。使う側は「ループを書かなくて良い」ように見えますが、SDK の内部では同じ処理が動いています。

自作した価値は、エージェントのプリミティブな処理を理解できたことです。SDK でトラブルが起きたときに「ループのどの段階で詰まっているか」を推測できるようになりました。
